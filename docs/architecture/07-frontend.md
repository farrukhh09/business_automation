# 07. Frontend (админ-панель, Next.js)

## 1. Стек и конфигурация
- Next.js (App Router, последняя стабильная), React, TypeScript `strict`, Tailwind CSS, ESLint.
- Библиотеки: `@tanstack/react-query` (запросы/кэш), `recharts` (графики), `leaflet` + `react-leaflet` (карты, OSM-тайлы с атрибуцией; компонент грузится через `next/dynamic` с `ssr:false`), `clsx`. Без тяжёлых UI-китов: собственные компоненты в `components/ui/`.
- Все запросы к backend идут на относительный `/api/...`; `next.config.ts` → `rewrites`: `/api/:path*` → `${BACKEND_INTERNAL_URL}/api/:path*` (default `http://localhost:8000`). CORS в браузере не нужен.
- `output: "standalone"` для Docker.
- Язык UI — русский. Формат дат `ДД.ММ.ГГГГ`, время `ЧЧ:ММ`, деньги `12 500 сомони` (`lib/format.ts`).

## 3. Авторизация
- `POST /api/auth/login` → access token в памяти (React context), refresh token в `localStorage` (`bakery.refresh`). При загрузке — `POST /auth/refresh`, при 401 — один refresh и повтор запроса; неудача → logout → `/login`.
- `RoleGate roles={["ADMIN"]}` скрывает недоступные действия; пункты меню «Пользователи», «Настройки» (редактирование) — только ADMIN. Бэкенд всё равно проверяет роль.

## 4. Разделы (SPEC §31–32)
Меню (порядок): Dashboard · Заказы · Клиенты · Товары · Доставка · Производство · Финансы · Статистика · Отчёты · FAQ · Диалоги · Настройки · Пользователи.

| Раздел | Содержание |
|---|---|
| Dashboard | StatCard: заказы сегодня, выручка сегодня, неоплаченные, новые клиенты, постоянные, доставка, самовывоз, ждут подтверждения, диалоги требуют внимания; таблица последних заказов; мини-график выручки за 14 дней |
| Заказы | фильтры (дата от/до, статус multi, оплата, тип получения, клиент/поиск), таблица колонок SPEC §17, пагинация; `/orders/new` — форма (клиент поиском, позиции из каталога, дата/время, тип, адрес/получатель); `/orders/[id]` — детали, смена статуса (только `allowed_transitions`), оплата (статус, платежи), редактирование (ADMIN — всё; OPERATOR — разрешённые поля), журнал изменений, missing_fields |

| Финансы | период (Сегодня/Вчера/Неделя/Месяц/Произвольный), date_basis; карточки: выручка · расходы · прибыль · рентабельность, затем оплаты/средний чек/заказы; график «выручка, расходы (столбцы) и прибыль (линия) по дням»; расходы по категориям; таблица расходов за период с фильтром по категории (добавить/изменить/удалить — только ADMIN, после изменения обновляются и карточки, и график) |

| Пользователи | ADMIN: список, создание, смена роли/пароля, деактивация |

## 5. UI-требования
- Адаптивность: sidebar сворачивается в drawer < 1024px; таблицы — горизонтальный скролл в контейнере или карточки на мобильных.
- Состояния: загрузка (skeleton/spinner), пусто (EmptyState), ошибка (сообщение `detail` из ApiError + повтор).
- Бейджи статусов с цветами из `lib/labels.ts`; все enum показываются русскими подписями.
- Мутации → toast + инвалидация соответствующих query.
- Никаких секретов во frontend; только `NEXT_PUBLIC_APP_NAME`.

## 6. Проверка
`npm run lint`, `npx tsc --noEmit`, `npm run build` должны проходить без ошибок.
