Каждое ключевое утверждение перепроверено на официальных страницах (taximaxim.tj, taximaxim.com, corp.taximaxim.ru, delivery.taximaxim.com, business.taximaxim.com, legal.taximaxim.com, legal.taximaxim.ru), на GitHub, в App Store и в документации Google. ## 1. Вывод и рекомендация

### Вердикт: **(C) официальный API не найден**

- Нет публичного, документированного или партнёрского API, через который бизнес мог бы **создать** курьерский заказ, **получить статус** или **отменить** его. Нет портала разработчиков, SDK, раздела «API» или отдельного соглашения об API. Это верно и для Таджикистана, и для России, и для лендинга доставки для магазинов.
- Юридические документы для TJ — это публичная оферта, лицензионное соглашение, политика конфиденциальности и правила бонусной программы. Документа для юрлиц или про API среди них нет.
- Вариант **(B) «по договору»** возможен только теоретически:
  - Код MAPS.ME (раздел 3.5) показывает, что «Максим» когда-то выдавал партнёру ключи `RefOrgId` / `access-token`.
  - Но та интеграция только **считала цену** и открывала приложение «Максим». Заказы она не создавала, не отслеживала и не отменяла.
  - Сейчас нигде нет официального предложения партнёрского или корпоративного API. Узнать, возможно ли это, можно только прямым запросом (раздел 4).
- **Эндпоинты, авторизация, payload:** официально не описаны нигде, поэтому здесь их нет. Код в разделе 2 — это **наш собственный** интерфейс, а не API «Максима».

### Главная оговорка: Душанбе

По официальному сайту на 2026-09-15 **не удалось подтвердить**, что «Максим» сейчас работает в Душанбе:
- В списке городов на taximaxim.tj только **Бустон (5027)** и **Худжанд (1449)**.
- Страница `/ru/3373-dushanbe/` отдаёт 404.
- Остальные «душанбинские» URL показывают контент Бустона или Худжанда (раздел 3.4).

Проверить на месте: открыть приложение «Максим» с геолокацией в Душанбе и посмотреть, доступны ли «Курьер» или «Доставка» («Купим и привезём»).

### Рекомендация для нашей системы (FastAPI + Next.js)

1. **Не делать «Максим» обязательной частью процесса заказа.** Курьер должен стоять за нашим интерфейсом `CourierProvider`.
2. **Фаза 1 — `ManualMaximProvider` (оператор делает всё руками):**
   - Админка показывает карточку «Вызвать курьера» с кнопкой копирования.
   - Оператор оформляет заказ в приложении «Максим» или по телефону **515** (если сервис работает в городе).
   - Затем вручную вносит данные курьера и статус.
3. **Фаза 2:** подключить `ApiProvider` к любой службе доставки, у которой есть **официальная** API-документация для Душанбе. Или к «Максиму», если он письменно предоставит API по договору.
4. **Автоматизацию Android-приложения «Максим» через Accessibility Service в продакшн не ставить** (разделы 2.3 и 5):
   - ToS прямо не запрещает её, но и не разрешает.
   - Политика Google Play запрещает автономные действия через AccessibilityService.
   - Android 13+ и новая верификация разработчиков дополнительно ограничивают такие приложения.
   - Допустим максимум помощник, который подставляет данные, а заказ каждый раз подтверждает человек. И только после письменного согласия «Максима».
5. **Не реверсить** приложение и не вызывать его закрытые эндпоинты (включая `cabinet.taximaxim.ru/...` из MAPS.ME) без договора.

## 2. Детали и примеры (наша сторона)

### 2.1 Интерфейс провайдера — **наш код, не API «Максима»**

```python
# app/delivery/providers.py  (our code — not Maxim's API)
from typing import Protocol, Literal
from pydantic import BaseModel

Status = Literal["pending_manual", "dispatched", "picked_up", "delivered", "cancelled", "failed"]

class DeliveryRequest(BaseModel):
    order_id: str
    pickup_address: str
    dropoff_address: str
    recipient_phone: str
    cash_to_collect_tjs: float | None = None
    notes: str | None = None

class DeliveryInfo(BaseModel):
    provider: str                     # "maxim_manual"
    external_ref: str | None = None   # free text typed by the operator
    status: Status
    courier_name: str | None = None
    courier_phone: str | None = None
    price_tjs: float | None = None

class CourierProvider(Protocol):
    async def create(self, req: DeliveryRequest) -> DeliveryInfo: ...
    async def get_status(self, order_id: str) -> DeliveryInfo: ...
    async def cancel(self, order_id: str, reason: str) -> DeliveryInfo: ...

class ManualMaximProvider:
    """Human-in-the-loop: creates a task for the operator; makes NO calls to Maxim."""
    async def create(self, req: DeliveryRequest) -> DeliveryInfo:
        # persist task in our DB, notify admin panel (websocket/push)
        return DeliveryInfo(provider="maxim_manual", status="pending_manual")
    # get_status / cancel read and write our DB; the operator updates them in the admin panel
```

### 2.2 Наш админ-эндпоинт (пример)

`PATCH /api/deliveries/{order_id}` — **наш API**:

```json
{
  "status": "dispatched",
  "courier_name": "Фарход",
  "courier_phone": "+992XXXXXXXXX",
  "external_ref": "Maxim, заказ через приложение, 14:05",
  "price_tjs": 18
}
```

Смена статуса может запускать сообщение клиенту в Instagram (RU/TJ) через **нашу** интеграцию с Instagram. «Максим» здесь не участвует.

### 2.3 Если оставлять опциональную Accessibility-автоматизацию

- Режим «только ассистент»: подставить адрес или телефон и остановиться. Заказ подтверждает человек.
- Флаг для отключения. При сбое — сразу переход на ручной сценарий.
- Никаких обходов капчи и антифрода, никакого чтения закрытых данных других приложений.
- Технические ограничения Android и Google Play — в разделе 5.

## 5. Ограничения и риски

### 5.1 Публичная оферта TJ (для заказчиков) — `https://legal.taximaxim.com/public-offer/?country=TJ`

- **Кто сторона:** «Сервис «Максим»». Юрлицо, ИНН и дата редакции не указаны.
- **1.1:** «Данный документ, адресованный **любому физическому лицу** (далее — Заказчик), является официальным предложением сервиса «Максим»».
  - Оферта TJ, как и российская, адресована **физлицам**.
  - Слово «юридическ» в тексте не встречается.
  - Договорных условий для бизнеса в Таджикистане публично нет.
- **1.5.10:** «Авторизованное мобильное приложение (Мобильное приложение) — программа для электронных вычислительных машин, устанавливаемая на мобильное устройство Заказчика и позволяющая автоматизировать процесс формирования заказов посредством сети Интернет.»
  - Здесь описано назначение самого приложения. **Это не разрешение на стороннюю автоматизацию.**
- **Разделы:** 1 Общие положения; 2 Предмет оферты; 3 Обязанности Сервиса; 4 Обязанности Заказчика; 5 Осуществление расчетов между Заказчиком и Партнером; 6 Ответственность Сторон; 7 Особенности заказа отдельных видов Услуг; 8 Порядок разрешения споров; 9 Особые условия.
- **2.1:** Заказчик может «безвозмездно разместить Заказ на оказание Услуг». Сам Сервис Услуги не оказывает — их оказывают **Партнеры** («лицо, самостоятельно, своими силами оказывающее Заказчику Услуги»).
- **3.5:** Сервис обязуется «своевременно обнаруживать и предотвращать попытки несанкционированного доступа к информации, предоставляемой Заказчиком».
- **Раздел 4:** только 4.1 («Заказывать Услуги с учетом времени…») и 4.2 («Указать существенные условия…»). **Запрета передавать данные авторизации третьим лицам, как в п. 4.3 российской оферты, в TJ-оферте нет.**
- **5.10:** «В случае отмены Заказчиком размещенного заказа, а также в иных случаях, когда Заказчику не были оказаны Услуги, денежные средства, зарезервированные на карте, возвращаются Заказчику.» Порядок отмены через API или программно не описан.
- **Автоматизация:** пунктов про ботов, скрипты, парсинг или сторонние программы нет. Текст извлечён автоматически; перед решением его должен прочитать человек. **Молчание оферты — не разрешение.**
- **Политика конфиденциальности (клиенты TJ):**
  - Про ботов и парсинг ничего нет.
  - Есть отсылка к «Правилам работы сервиса «Максим»» (7.9.5). Самих Правил нет в перечне правовых документов TJ; найти их и проверить содержание — **не подтверждено**.

### 5.4 Google Play и Android: ограничения для Accessibility-автоматизации

- **Политика Google Play** (если приложение-автоматизатор публикуется в Play):
  - «Any use of the Accessibility API that enables an app to autonomously initiate, plan, and execute actions or decisions is strictly prohibited.»
  - Исключение — только для приложений с `isAccessibilityTool="true"`, созданных для людей с инвалидностью.
  - Остальным нужны заметное раскрытие прямо в приложении и явное согласие пользователя.
  - Приложения, которые используют AccessibilityService и таргетируют Android 12+, с 3 ноября 2021 года заполняют Permission Declaration Form и проходят одобрение Google Play.
- **Android 13+, «Restricted settings»:**
  - Если приложение установлено в обход магазина (sideload), доступ к специальным возможностям может быть заблокирован.
  - Пользователь снимает блок вручную: Настройки → Приложения → приложение → ⋮ → «Разрешить ограниченные настройки».
- **Верификация разработчиков Android:**
  - С сентября 2026 года на сертифицированных устройствах в Бразилии, Индонезии, Сингапуре и Таиланде ставятся только приложения верифицированных разработчиков, в том числе при sideload.
  - С 2027 года — во всём мире, то есть и в Таджикистане.
  - Исключения: установка через ADB, «advanced flow» с одноразовой настройкой, аккаунт ограниченного распространения (до 20 устройств без удостоверения личности).
